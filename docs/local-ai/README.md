# Local AI writing assistant (experimental)

This branch implements an authenticated project sidebar and opt-in CodeMirror inline suggestions using the OpenAI Responses API. It was inspired by AI Agent for Overleaf and Overleaf Copilot (MIT), but does not embed their browser extensions. The existing editor autocomplete remains available and takes precedence over accepting an AI suggestion.

On the web service set `OPENAI_API_KEY` and `OVERLEAF_AI_MODEL` in a private server-side environment. Both are required. Alternatively, launch the service with `python3 tools/local-ai/run-with-config.py /path/to/private-ai-config.yaml COMMAND [ARGS...]`, which reads `openai.api_key` and `openai.model` from a mode-0600 YAML file and passes them to the process environment. The runtime must have PyYAML and permission to read the file. Container startup and private mounts must be wired explicitly; the wrapper has not yet been deployed. Never place the key in client-side code or Git. AI requests require an authenticated project member, are rate-limited per user and project, and send the selected text, prompt or nearby source to OpenAI; requests set `store: false`. The model and key are shared by users; no user budget accounting is implemented. Inline completion is opt-in per browser, and has a 900 ms debounce. Chat history is held in the open panel only. The AI output is never silently applied: polishing requires a selection and an explicit replace; the editor checks the document has not changed while waiting.

Explain-error currently accepts pasted log text rather than automatically reading compile logs. AlphaXiv research search is available to authenticated project members through a read-only MCP discover_papers call; it requires the server-side ALPHAXIV_API_KEY. External service traffic can use OVERLEAF_AI_HTTPS_PROXY without changing the rest of the application. An isolated instance was built and verified with real provider requests and a browser, including chat, search, selection polishing, inline suggestions, Tab acceptance and error explanations. The production switch remains pending. Configuration changes are written to the runtime environment file but require a service restart to take effect. Voice transcription is not implemented.
